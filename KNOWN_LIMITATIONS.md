# Ограничения 0.5.3

CUDA/NCCL, custom FA2, POWER9 и ATS не проверены на реальном сервере в этой ревизии. CPU тесты не удостоверяют аппаратный execution. ATS требует аппаратных capabilities, c++ compiler и managed persistent shards; activations и active FSDP groups остаются в обычной VRAM. Memory planner выдаёт оценки, не admission guarantee.

H3 Ulysses допускает произвольное число ranks; при пустом token shard используется явно отмеченный replicated compute. Qwen text использует token/GQA sequence path, vision compute реплицирован. Пользовательский LoRA/ControlNet/weight patch remote contract не реализован. Spectrum — approximate и требует оценки качества отдельно от базового режима.

В pipeline с Qwen idle=cpu_shards Config должен иметь placement=cpu; для gpu/ats используйте release/keep. Kept workers не накапливают staged prompt tensors между runs; JSON history пока сохраняется. UI migration покрывает известные LiteGraph array-link layouts; API migration предпочтителен для связанных legacy controls и неизвестных UI formats.

Normalized FP16 exchange и reduced cuBLAS reductions требуют correctness/performance проверки на V100. При исчерпанной auto estimate используется minimum chunk до 256 tokens, а не token=1; возможен реальный CUDA OOM. Cache estimate не учитывает все виды fragmentation. Checkpoint-bound fast path относится к FP16 Linear; INT8 dequant path пока прежний. Profiler/Triton smoke требуют CUDA/CUPTI/совместимой custom сборки; они не пройдены на текущем CPU runtime. Наличие/выбор provider не равно его фактическому применению ко всем Qwen groups.

MLP off по умолчанию может требовать больше VRAM; auto/manual включается пользователем явно. При keep=true отмена in-flight RPC не убивает отдельные ranks: здоровый текущий вызов заканчивается в фоне, результат отбрасывается, следующих шагов нет. Следующая задача ждёт drain. Повреждённые CUDA/NCCL contexts и незавершённая загрузка не сохраняются. Зависший kernel требует принудительной остановки, с потерей RAM shards. Keep не гарантирует сохранение при restart/provider/config/checkpoint change или явном снятии preserve-флага. В RAM сохраняется не более одного владельца каждой роли, но H3+Qwen CPU caches вместе могут существенно расходовать 128 GB.

0.5.3: RAM parking GPU/ATS проверен на CPU tensors с mocked DTensor ownership и маленькой native H3; не на реальном FSDP/NCCL/managed allocator. Для аппаратной проверки добавлен `probe_h3_cuda.py --ram-roundtrip` и `accept_h3.py --ram-roundtrip`. Реконструкция graph и H2D добавляют отдельную задержку между runs; внутри sampling переносов нет. `prefetch_policy=manual` не уменьшает 1/2 автоматически и может вызвать OOM. FP32 wire использует больше communication workspace, чем normalized FP16; выбор пути сам по себе не гарантирует возврат 45s. Не измерен вклад 50 дополнительных MAX collectives, не подтверждена причина разницы 45→80s.
